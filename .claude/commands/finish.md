# Команда /finish

Прогон пред-коммитного чек-листа и подготовка коммита. Каждый пункт — проверить и **исправить**,
если нарушено. Если что-то не проходит — остановиться и сообщить, не коммитить.

## 1. Полный прогон

`npm run lint` + `npm run build` + `npm run test:run` — **все три**, ни один не заменяет другой
(`rules.md` §5). Это единственный полный прогон; по ходу работы гонялось только точечное.

Документационный коммит (в диффе только `.md` и `.claude/`, ни одного файла `src/` и конфигов
сборки) — прогоны пропускаются, и это озвучивается явно: «тесты не запускались: кода в диффе нет».

## 2. Безопасность (`rules.md` §6)

- В диффе нет реальных `idInstance`/`apiTokenInstance`, в том числе в тестах и `.env*`.
- Нет `console.log` вне `import.meta.env.DEV`; URL запросов GREEN-API (в нём токен) не логируется.
- Нет `dangerouslySetInnerHTML`.

## 3. Код и стиль

- Цвета, кегли, радиусы — через `var()`; литералы только в `styles/tokens/`.
- Тесты на новое/изменённое есть (skill `frontend-patterns` §«Тестирование»).

## 4. Документация

- **README** актуален: что это, как запустить локально (`npm install`, `npm run dev`), что нужно
  от GREEN-API (инстанс MAX, авторизация по QR, пустой `webhookUrl`), ссылка на деплой, если есть.
- Изменился скоуп или принято решение (хранение учётных данных, прокси, деплой) →
  `.docs/requirements.md` или «Зафиксированные договорённости» в `.claude/CLAUDE.md`.
- Проверено на живом инстансе то, что в skill `green-api` помечено «не проверено», → снять
  пометку и записать факт.

## 5. Коммит и слияние в `dev`

- Коммит в ветке задачи, формат `<тип>(область): описание на русском` (`rules.md` §4).
- **Без строки `Co-Authored-By`.**
- `git checkout dev` → `git merge --no-ff <ветка>`; ветку задачи не удаляем (`rules.md` §4).
  Конфликт при слиянии — остановиться и показать Диме, не разрешать молча.

## 6. Пуш — только Дима, и только в конце

- По задачам **не** пушим: `/finish` заканчивается слиянием в `dev`, команду пуша не выдаёт.
- Когда Дима скажет «отправляем» — выдать в блоке кода команду пуша ветки `dev` с установкой
  upstream и напомнить, что PR `dev → main` он открывает в GitHub.
- Напомнить, что проверить вживую: сквозной сценарий из `.docs/requirements.md` на реальном
  инстансе (`rules.md` §2).
