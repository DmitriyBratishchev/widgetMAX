# Команда /research

Режим ресёрча по теме: $ARGUMENTS (если пусто — спросить тему).

Правила (`.claude/rules.md` §2):

1. Создать/обновить `.research/{topic-name}/research.md` по шаблону из `.research/README.md`
   (статус: `draft`).
2. Обсуждать, дополнять заметки, исследовать варианты (плюсы/минусы/сложность), фиксировать
   находки и рекомендацию. Триггеры входа: «обсудим», «поресерчим», «подумаем», «исследуй»,
   «варианты», «как лучше», «давай разберём», «покопай», «сравни».
3. **Факты о GREEN-API — с доказательством**: чем проверено (запрос с фейковыми данными,
   документация, живой инстанс Димы) и когда. Проверенное на живом инстансе переносится в skill
   `green-api` с пометкой снятого «не проверено». Реальные учётные данные в ресёрч не пишем.
4. Изображения (скриншоты web.max.ru, макеты) класть рядом с `research.md`.
5. **НЕ создавать спеку и НЕ писать код**, пока Дима явно не скажет «делаем», «пиши спеку»,
   «создай задачу».
6. Статусы файла: `draft` → `in-progress` → `ready-for-task` → `archived`.
7. При переходе к задаче — сослаться на ресёрч в `spec.md` (не дублировать).

## Перевод в `ready-for-task`

**Уровень объявляется здесь, а не в начале.** `ready-for-task` ставится **только вместе с
двумя вещами**: меткой уровня в шапке и соответствующей ей разбивкой.

```
**Статус:** ready-for-task
**Уровень:** задача | эпик | справочник
```

Рабочий критерий: **куски нарезки сами дробятся на фазы → эпик; куски и есть фазы → задача;
`WM-NN` из ресёрча не растёт вовсе → справочник.** Не удаётся решить — оставить `in-progress`.

| Уровень | Обязательная разбивка | Кто потребляет |
|---------|----------------------|----------------|
| **задача** | **карта фаз** — та же таблица, что ляжет в `plan.md` | `/task-start` (сценарий B) |
| **эпик** | **таблица задач `WM-NN`** (формат ниже) | `/epic-next` |
| **справочник** | не нужна | никто: материал **цитируют** другие ресёрчи и спеки |

`ready-for-task` без разбивки — тупик: ни `/task-start`, ни `/epic-next` не смогут выбрать, что
делать дальше.

> Ориентир при нарезке — фаза должна помещаться примерно в половину контекста чата вместе с
> тестами и отладкой (`rules.md` §3). Нарезаем **по смыслу** (слой, экран, метод API).

**Метка — живая.** Изменилась оценка по ходу — метка меняется вместе с разбивкой, с причиной в
тексте. Задача разрослась в эпик уже в реализации — старый `WM-NN` остаётся за сделанным, не
начатые фазы становятся задачами с новыми номерами.

### Разбивка для уровня «эпик»

```
| WM-NN | Задача | Зависит от | § ресёрча | Источник | Статус |
```

- `WM-NN` — сквозной номер задачи (ветка `feature/WM-NN-<kebab>`, коммиты `[WM-NN]`).
- `Зависит от` — какие задачи должны быть слиты в `dev` раньше.
- `§ ресёрча` — разделы, на которые сошлётся JIT-спека (спека **ссылается**, не дублирует).
- `Источник` — `план` (была в разбивке изначально) · `прогон WM-NN` · `дефект` · `follow-up`.
  Задачи, родившиеся по ходу эпика, дописываются **сразу**, с источником — иначе разрастание
  эпика невидимо.
- `Статус` — `план` → `в работе` → `в dev WM-NN@YYYY-MM-DD`. Отмечается при слиянии в `dev`.

Для эпика здесь же заводится **накопительный «Чек-лист сквозных сценариев»**:

```
| # | Экран | Действие | Ожидание | Приоритет |
```

Правило накопления — условием, а не перечнем: «**любая** задача эпика, добавляя экран или
поведение, дописывает сюда строки». Первые строки — сценарий приёмки из `.docs/requirements.md`.
Чек-лист потребляет `/task-check`, а по нему Дима проверяет сквозной сценарий на живом инстансе.

### Разбивка для уровня «задача»

**Карта фаз** — тот же формат, что в `.specs/templates/plan.md`, чтобы перенести без
переписывания:

```
| Фаза | Цель | Трогает GREEN-API | Статус |
```

Фазы расписываются детально **не здесь**: ресёрч даёт нарезку и границы, детали — JIT в
`plan.md` перед реализацией каждой фазы.

## Что дальше (после перевода в `ready-for-task`)

Подсказать следующий шаг по объявленному уровню — мягко, ничего не блокируя:

| Уровень | Следующий шаг | Что произойдёт |
|---------|---------------|----------------|
| **задача** | **`/task-start`** | сценарий B: `spec.md` + `plan.md` из ресёрча, код не пишется |
| **эпик** | **`/epic-next`** | выберет первую задачу эпика и соберёт промпт для нового чата |
| **справочник** | ничего | в работу не берётся; его **цитируют** |

Называть **только следующий шаг** — полная цепочка описана в `.claude/CLAUDE.md` §«Рабочий
процесс».
