# Команда /task-start

Начни новую задачу по ритуалу проекта. Название/описание задачи: $ARGUMENTS
(если пусто — спросить).

## Шаг 0. Определить сценарий

Проверить, есть ли **связанный ресёрч** в `.research/` со статусом `ready-for-task` (по теме
задачи; кандидатов несколько — уточнить через AskUserQuestion). Если есть — прочитать метку
**`Уровень:`** (строго в шапке, до первого `##`) и маршрутизировать:

| Ситуация | Что делать |
|---|---|
| Ресёрча нет | **Сценарий A** — обычный старт |
| `Уровень: задача` | **Сценарий B** — переход из ресёрча, только документация |
| `Уровень: эпик` | Задача **из таблицы эпика** (указана в `$ARGUMENTS` или её выбрал `/epic-next`) → **сценарий A** со ссылкой на § ресёрча. Задача не указана → отправить к **`/epic-next`** и остановиться |
| `Уровень: справочник` | **Сценарий A**, сославшись на ресёрч в спеке |
| **Метки нет** | **Не угадывать по содержимому.** Предложить уровень через AskUserQuestion (критерий — `/research` §«Перевод в `ready-for-task`»), проставить метку в шапку. Разбивки нет вовсе — её сначала заводят в ресёрче, не выдумывают молча здесь |

## Сценарий A — обычный старт

1. **AskUserQuestion** с названием задачи и вариантами:
   - **Да** — переключить ветку, создать новую, начать планирование
   - **Да, но...** — то же, но сначала запросить дополнительную информацию
   - **Нет** — ничего не делать
2. После «Да»/«Да, но...»:
   - `git status` — рабочее дерево чистое? Нет → показать Диме и остановиться.
   - `git checkout dev`, затем `git checkout -b feature/WM-NN-<kebab>`. Номер `WM-NN` — из
     таблицы эпика, а для задачи вне эпика — следующий свободный (по `.specs/features/` и
     коммитам `[WM-NN]`). Мелкая разовая правка (`fix/`, `chore/`, `docs/`) идёт без номера и
     без спеки. **`git pull` не делаем** — remote трогает только Дима.
   - Ветка уже существует → **AskUserQuestion**: «Переключиться» или «Удалить и создать
     заново» (без уникальных коммитов — можно просто переключиться).
3. **EnterPlanMode** и спека задачи. Режим планирования разрешает писать **только файл плана
   харнеса**, поэтому:
   - в режиме планирования черновики `spec.md`, `plan.md` (+ `tasks.md`) пишутся **в файл плана**
     — по шаблонам `.specs/templates/`, сжато;
   - **первый шаг после одобрения** — перенести их в `.specs/features/{WM-NN-задача-kebab}/`.
     Дальше источник правды — `.specs/` (он в git), файл плана харнеса больше не правится.
   - `spec.md` — проблема, решение, **нумерованные** критерии с доказательством.
   - Масштаб «среднее» и выше — ещё `plan.md` и `tasks.md`. Задача по умолчанию — **одна фаза**
     (`.claude/CLAUDE.md` §«Зафиксированные договорённости»); делить на фазы — только если явно
     не влезает в один чат, и сказать об этом Диме до старта.
   - Есть связанный ресёрч — ссылаться на его §, не дублировать.
4. Определить **масштаб** (`rules.md` §3) и **уровень риска** (`rules.md` §4).
5. Перед работой в зоне — skills: `frontend-patterns` (любая работа в `src/`), `green-api`
   (запросы, опрос уведомлений, chatId).

**Что дальше:** реализация в этом же чате → `/task-check` (по желанию) → `/finish` (коммит задачи
и слияние в `dev`). Задача из нескольких фаз — `/finish` после каждой, слияние на последней.

## Сценарий B — переход из ресёрча (документация, без кода)

> Ресёрч обычно сжигает контекст чата, а спека нужна **в git** — иначе новый чат её не увидит.
> Поэтому спека и план коммитятся отдельно от кода, а реализация начинается в чистом контексте.

1. **Ветка.** Ресёрч ещё не в `dev` → остаться в его ветке: ресёрч + спека + план уезжают одним
   слиянием. Ресёрч уже в `dev` → `git checkout dev` → `git checkout -b docs/WM-NN-<kebab>`.
   Ветку реализации `feature/WM-NN-…` здесь **не** создавать.
2. **EnterPlanMode** (черновики — в файле плана, перенос после одобрения, как в сценарии A) и
   документация в `.specs/features/{WM-NN-задача-kebab}/`:
   - `spec.md` — ссылается на § ресёрча. Статус `УТВЕРЖДЕНО` (решения уже приняты в ресёрче).
   - `plan.md` — **карта фаз** из ресёрча целиком (статусы `PROPOSED`); детально — только
     первая фаза.
3. **Код НЕ писать.**
4. **Завершить подсказкой:** `/finish` — коммит документации и слияние в `dev` (прогоны
   пропускаются: кода в диффе нет) → в новом чате `/task-start WM-NN` под реализацию (спека уже
   есть — дописать фазу, не создавать заново).

## Требования

- Все пути к файлам — реальные; без учётных данных GREEN-API.
- Каталог спеки уже есть (очередная фаза существующей задачи) → новую спеку не создавать:
  **дописать фазу** в `plan.md` (накопительно) и при необходимости уточнить критерии в `spec.md`.
