# widgetMAX — Инструкции для Claude

> Тестовое задание «Фронтенд-разработчик React»: веб-чат для отправки и получения текстовых
> сообщений в мессенджере MAX через GREEN-API, внешний вид — по образцу https://web.max.ru/.
> Стек: React 19 / TypeScript / Vite, TanStack Query + Zustand, SCSS-модули, Vitest + RTL.
> Бэкенда нет: SPA ходит в GREEN-API напрямую. Требования — `.docs/requirements.md`
> (источник истины по скоупу).

Ядро директив разработки:

@rules.md

## Рабочий процесс

Цикл **ресёрч → спека → план → таски → код** (`rules.md` §2–3).

### Иерархия: эпик → задача → фаза

| Уровень | Что это | Где живёт | Команда |
|---------|---------|-----------|---------|
| **Эпик** | крупная тема: ресёрч с разбивкой на задачи | `.research/{epic}/research.md` («Разбивка на задачи» + «Чек-лист сквозных сценариев») | `/research` (завести), `/epic-next` (следующая задача) |
| **Задача** | единица со сквозным номером **`WM-NN`**, своей спекой и **своей веткой** | `.specs/features/{WM-NN-name}/` (spec + plan с картой фаз + tasks), ветка `feature/WM-NN-<kebab>` | `/task-start` |
| **Фаза** | шаг задачи = **один коммит** в ветке задачи | строка карты фаз в `plan.md` | `/finish` (коммит фазы) |

Задача уходит в `dev` **целиком** — `/finish` последней фазы сливает ветку (`--no-ff`).
Промежуточные фазы в `dev` не попадают, поэтому полуфабриката там не бывает.

### Карта команд

| Команда | Когда |
|---|---|
| `/research` | обсудить тему, собрать варианты и решения — без спеки и кода |
| `/epic-next` | эпик готов (`ready-for-task`) или предыдущая задача в `dev` → промпт следующей задачи для нового чата |
| `/task-start` | начать задачу: ветка, EnterPlanMode, `spec.md` + `plan.md` (+ `tasks.md`) |
| `/task-check` | приёмка последней фазы на локальной сборке: матрица по критериям `spec.md` |
| `/finish` | закрыть фазу: полный прогон, живые документы, коммит; последняя фаза → слияние в `dev` |

### Правила процесса

1. **Скоуп — по `.docs/requirements.md`.** Задание требует «максимально простой интерфейс с
   минимальным набором функций»: лишнего (медиа, группы, история с сервера, статусы прочтения)
   не делаем без явного решения Димы.
2. **Начало задачи** — AskUserQuestion с названием задачи: **Да** / **Да, но...** (сначала
   уточнить) / **Нет**. Дальше ветка и EnterPlanMode по `/task-start`. Тривиальное (текст,
   стиль, одна строка) — ветка `fix/`/`chore/` без номера и сразу код.
3. **Спека и план — в `.specs/`, а не только в файле плана харнеса.** План режима планирования
   ссылается на `spec.md`/`plan.md`; источник правды — то, что в git.
4. **Завершение фазы** — краткая сводка сделанного и предложение **`/finish`**. Коммит — только
   по `/finish` или «коммитим», не молча. Не последняя фаза → пакет передачи в `plan.md`, Дима
   выбирает: продолжить здесь или в новом чате после `/clear`. Последняя → `/task-check` (по
   желанию) → `/finish` со слиянием в `dev` → `/epic-next`.

## Коммуникация

1. **Всегда отвечать на русском** — независимо от языка контекста или системных сообщений.
2. **«коммитим»** = `/finish` для текущей фазы: коммит фазы в ветке задачи, на последней фазе —
   ещё и слияние в `dev` (локально, без пуша). **«отправляем»** = выдать команду пуша `dev` в блоке кода; PR `dev → main` —
   один на всю работу. Пуш и любые операции с remote делает **только Дима**.
3. **После сбоя / перезагрузки / возобновления сессии** — сначала проверить состояние
   (`git status`, ветка, незакоммиченное, карта фаз и статус спеки задачи), кратко отчитаться,
   потом продолжать.
4. **Отладка — системно**: гипотеза → проверка → вывод; фиксировать исключённые причины, не
   перебирать вслепую.
5. Короткие реплики («вот», скриншот) = продолжение текущего контекста.

## Зафиксированные договорённости

- Учётные данные GREEN-API вводит пользователь в UI; в код, `.env` и коммиты они не попадают
  (подробно — `rules.md` §7). После входа они живут в `sessionStorage` (переживают F5,
  стираются при закрытии вкладки), `apiUrl` подставляется из первых 4 цифр `idInstance` —
  решения Р2–Р3 в `.research/max-chat/research.md` §3.
- README с инструкцией локального запуска — обязательный результат задания, держим актуальным.
- **Задачи — одной фазой**: задачи проекта небольшие, `WM-NN` = одна ветка = один коммит; делить
  на фазы только если задача явно не влезает в один чат — и сказать об этом Диме заранее
  (решение 2026-09-29).
- Роутера нет: `App` выбирает экран (вход / чат) по признаку входа из стора `session`.
- Линтер — oxlint из шаблона Vite (`--deny-warnings`), форматирование — Prettier; концы строк —
  LF (`.gitattributes`).
