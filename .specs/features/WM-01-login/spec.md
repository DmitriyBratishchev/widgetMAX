## Проблема

Входа нет — шаг 1 сценария приёмки (`.docs/requirements.md`: «вводит свои учётные данные
GREEN-API») не выполним, а без учётных данных недоступны все остальные методы API.

## Решение

- Единственный транспорт `api/`: URL по форме из skill `green-api` §2, ошибка — по HTTP-статусу,
  тело ответа с ошибкой не разбирается (ресёрч §2.3).
- Вход = `GetStateInstance` вернул `authorized`; иное состояние — понятная причина.
- Стор `session` с persist в `sessionStorage` (ресёрч §3 Р2).
- Форма входа: `apiUrl` подставляется из первых 4 цифр `idInstance` (§2.2, Р3).
- Выбор экрана в `App` по признаку входа, без роутера (Р1); экран чата — оболочка с «Выйти».

## Сценарии использования

1. Пользователь вводит `idInstance` → поле `apiUrl` заполняется само → вводит токен → «Войти» →
   видит экран чата.
2. Токен неверный → под формой «Неверный idInstance или apiTokenInstance», остаётся на входе.
3. Инстанс не авторизован в MAX → причина и подсказка (отсканировать QR-код в кабинете).
4. F5 на экране чата → остаётся на экране чата.
5. «Выйти» → экран входа, учётные данные стёрты.
