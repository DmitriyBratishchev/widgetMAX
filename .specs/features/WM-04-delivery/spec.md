## Проблема

Сквозной сценарий 1–5 (`.docs/requirements.md`) работает с WM-03, но к отправке проект не готов:
пункт требований 4 «внешний вид — по образцу web.max.ru» закрыт частично (общая полоса-шапка, на
узком экране две колонки не помещаются), а из «Что сдаётся» нет ссылки на сервис в Интернете и
скриншотов.

## Решение

Решения на старте (Дима, 2026-09-29): деплой — **GitHub Pages**; из отложенного в WM-02/WM-03 берём
**сортировку чатов**, индикатор статуса опроса — нет; вёрстка — по образцу web.max.ru на усмотрение
исполнителя; скриншоты — `docs/screenshots/` + README. Причины — ресёрч §5.4.

1. **Раскладка web.max.ru**: две колонки на всю высоту. Сайдбар: шапка («Чаты», «Инстанс N»,
   «Выйти»), форма нового чата, список (аватар · номер · время · превью). Колонка чата: шапка
   («Назад», аватар, номер), лента пузырей с «хвостом», поле ввода-«пилюля» и круглая кнопка
   отправки с иконкой (`aria-label` «Отправить» / «Отправляем…»). Аватар — кружок с двумя
   последними цифрами номера (имён у нас нет).
   **Уточнение по скриншоту web.max.ru** (Дима, 2026-09-29): левую колонку навигации (Все / Новые /
   Каналы…) не делаем; лента и поле ввода — колонка **700px** по центру, пузырь — до **488px**; поле
   ввода «парит» белой карточкой над фоном чата, без полосы на всю ширину, сообщения под ним не
   видны (это блок под лентой, а не слой поверх); фон чата — **градиент** (фирменный узор — бренд, не
   берём). Пустые состояния на цветном фоне — белые плашки.
2. **Узкий экран** (`@include narrow`, ≤768px): одна колонка — без открытого чата список, с открытым —
   чат; «Назад» закрывает чат (`activeChatId = null`) и возвращает к списку. На широком экране
   «Назад» скрыта стилем. Переключение — атрибут `data-view="list|chat"` на корне страницы.
3. **Сортировка**: новое сообщение (исходящее из `SendMessage` или из очереди) поднимает свой чат в
   начало `chats`; дубль по `idMessage` порядок не трогает. Порядок — в сторе, переживает F5.
4. **Состояния экрана** — аудит ниже; недостающего нет, покрытие тестами фиксируем.
5. **Деплой**: `base: './'` в `vite.config.ts` — относительные пути работают и под `/widgetMAX/` на
   Pages, и в корне локально; роутера нет — SPA-fallback не нужен (ресёрч §3 Р1). Workflow
   `.github/workflows/deploy.yml`: push в `main` + ручной запуск → `npm ci` → `test:run` → `build` →
   upload/deploy Pages. Секретов в сборке нет: учётные данные вводятся в UI, `VITE_*` не используются.
6. **README**: ссылка на сервис `https://dmitriybratishchev.github.io/widgetMAX/`, скриншоты, деплой,
   «Как пользоваться» с узким экраном и сортировкой, устройство кода.

## Сценарии использования

1. Широкий экран: список чатов слева, открытый чат справа, «Назад» не видна.
2. Телефон: список чатов → тап по чату → чат на весь экран → «Назад» → список.
3. Собеседник ответил в чат внизу списка → чат поднялся наверх.
4. Проверяющий открывает публичный адрес, входит своими данными и проходит сценарий 1–5.
