## Проблема

Дефекты доступности из §3.2 ресёрча. Каждое место перепроверено по коду `dev` после WM-06
(`d304af1`) — подтвердились все; расчёт контраста и проверка фокуса нашли ещё три места (помечены
**новое**; Дима включил их в скоуп — AskUserQuestion, 2026-09-29).

- `--color-focus-ring: blue-100` (#e3ecff): на белом 1,19:1 при норме 3:1 (WCAG 1.4.11); на
  активном чате (`--color-chat-item-active` — тоже blue-100) 1,00:1 — кольца нет; на градиенте
  фона чата (кольцо поля ввода `.row:focus-within`) 1,39–1,72.
- `--color-text-muted: gray-400` (#9aa1ad): на белом 2,60, на наведённом чате (gray-100) 2,24, на
  активном чате и своём пузыре (blue-100) 2,19 — время и пустой список, 12–13px, норма AA 4,5.
- **Новое:** `--color-danger: red-500` (#e5484d) на белом 3,91 — все тексты ошибок (13px) и плашка
  остановки опроса, норма 4,5.
- **Новое:** рамка `Input` — `--color-border` (gray-200) на белом 1,30 — граница поля ввода
  (WCAG 1.4.11), норма 3.
- `MessageList`: live-региона нет — входящее сообщение скринридер не объявляет; направление
  передано только цветом и выравниванием. `<ol>` появляется вместе с первым сообщением (регион,
  вставленный вместе с содержимым, не объявляется), а без `key` смена чата меняет детей того же
  узла — будь там регион, он зачитал бы историю чата целиком.
- `ChatPage`: плашка WM-06 (`role="alert"`) стоит в двух ветках JSX (чат / заглушка) — при открытии
  и закрытии чата перемонтируется, и скринридер объявляет её заново.
- Фокус: «Назад» (`closeChat`) размонтирует саму кнопку — фокус падает на `body`; после открытия чата
  фокус остаётся на кнопке списка (на узком экране список скрыт — фокус теряется); при ошибках входа
  фокус никуда не уходит.
- **Новое:** кнопка, которая блокируется на время запроса (`disabled`), теряет фокус → `body`:
  «Войти» при отказе GREEN-API, «Создать чат» при отказе `CheckAccount`, «Отправить» при нажатии
  кнопки (не Enter).

## Решение

### 1. Токены (`_palette.scss`, `_semantic.scss` — литералы только там)

- Палитра: `+ --palette-blue-700: #1a47b8`, `+ --palette-gray-500: #868d99`,
  `--palette-red-500 → --palette-red-600: #c9303a`, `− --palette-gray-400` (больше не используется).
- Семантика: `--color-focus-ring: blue-700`, `--color-text-muted: gray-600`,
  `--color-danger: red-600`, `+ --color-input-border: gray-500` → рамка `Input`.
- Разделители колонок и рамка кнопки «Выйти» остаются на `--color-border`: это не граница поля, а
  кнопку опознаёт её текст.
- *muted = gray-600, как secondary.* Любой серый светлее gray-600 даёт < 4,5 на blue-100 (у gray-600
  — 4,60), а время стоит и на активном чате, и на своём пузыре. Иерархия «время тише превью»
  держится кеглем (12 против 13px). Токен muted оставлен — роль отдельная.

### Контраст

Формула WCAG 2.x (относительная яркость sRGB, `(L1 + 0,05) / (L2 + 0,05)`); разовый node-скрипт в
scratchpad, без зависимостей. Норма: текст — 4,5 (AA, мелкий кегль), граница поля и кольцо фокуса —
3 (1.4.11).

| Цвет | Фон | Было | Стало | Норма |
|---|---|---|---|---|
| `--color-focus-ring` → blue-700 #1a47b8 | white / gray-50 / gray-100 | 1,19 / 1,10 / 1,02 | 7,96 / 7,36 / 6,85 | 3 |
| `--color-focus-ring` | blue-100 (активный чат) | 1,00 | 6,71 | 3 |
| `--color-focus-ring` | градиент blue-300 → cyan-300, минимум по 21 точке | 1,39–1,72 | 3,91 | 3 |
| `--color-text-muted` → gray-600 #626a78 | white / gray-100 / blue-100 | 2,60 / 2,24 / 2,19 | 5,45 / 4,69 / 4,60 | 4,5 |
| `--color-danger` → red-600 #c9303a | white (все тексты ошибок, плашка остановки опроса) | 3,91 | 5,29 | 4,5 |
| `--color-input-border` → gray-500 #868d99 | white | 1,30 | 3,34 | 3 |
| `--color-text-secondary` gray-600 (без изменений) | white / gray-100 / blue-100 | 5,45 / 4,69 / 4,60 | — | 4,5 |
| `--color-accent` blue-500 (ссылка, «Назад»); белый текст на accent (кнопка) — без изменений | white / blue-500 | 4,50 (4,503) | — | 4,5, впритык |

Кольцо на основной кнопке (фон blue-500) с ней сливается (1,77), но граница кольца — с белым фоном
вокруг (7,96): кнопка заметно «вырастает», фокус виден.

### 2. Лента: `role="log"` + явный `aria-live="polite"`

- На **постоянной обёртке** `<div>` в `MessageList`; внутри — пустое состояние или
  `<ol aria-label="Сообщения">`.
- *Почему `log`, а не голый `aria-live`:* роль — семантика «журнал, новое в конце»; объявляются
  только добавления (`aria-relevant` по умолчанию `additions text`) и вежливо, не перебивая.
  Явный `aria-live="polite"` — для связок скринридер/браузер, которые не выводят его из роли.
- *На обёртке, а не на `<ol>`:* роль на `<ol>` отняла бы у него `list`, и `<li>` остались бы без
  родителя-списка. Обёртка живёт и в пустом состоянии — первое сообщение тоже объявится.
- *История при открытии не зачитывается:* `ChatPage` оборачивает ленту и поле ввода в
  `<Fragment key={chatId}>` — у каждого чата свой регион, а содержимое, с которым регион смонтирован, не объявляется.
- *Свои сообщения тоже объявляются* («Вы: …») — это подтверждение отправки. Отдельный объявитель
  только входящих — лишний код и дубль текста.
- *Плашка WM-06* рендерится один раз, в постоянной позиции `<main>` (до условной ленты/заглушки):
  не перемонтируется при открытии и закрытии чата. Она вне `log` — регион её не дублирует.

### 3. Направление сообщения

В начале `<li>` — `<span>` «Вы:» / «Собеседник:», визуально скрытый миксином `visually-hidden`
(новый `src/styles/mixins/_a11y.scss`; `1px` и `clip` — служебные значения приёма, как `768px` в
`_breakpoints.scss`).

### 4. Фокус

| Событие | Куда фокус | Как |
|---|---|---|
| «Назад» (узкий экран) | кнопка закрытого чата в списке | `ChatList`: карта `chatId → кнопка` (ref-колбэк React 19 с очисткой) и эффект по `activeChatId`: был `X`, стал `null` → фокус кнопке `X`. `null` ставит только `closeChat`; к моменту эффекта `data-view="list"` уже в DOM — список виден |
| Открытие чата: клик в списке, «Создать чат», «Перейти в чат», F5 с открытым чатом | поле «Сообщение» | `MessageComposer` монтируется заново на каждый чат (тот же `<Fragment key={chatId}>`) → эффект при монтировании фокусирует поле |
| Нажатие «Отправить» | поле «Сообщение» | `submit()` после `mutate` фокусирует поле (при Enter фокус и так там) |
| Вход: ошибка валидации | первое невалидное поле (idInstance → apiTokenInstance → apiUrl) | `flushSync(setErrors)` → `focus()`: к моменту фокуса у поля уже `aria-invalid` и `aria-describedby` — скринридер прочтёт текст ошибки вместе с полем |
| Вход: отказ GREEN-API | поле idInstance | `mutate(values, { onError })`. Текст ошибки объявляет `role="alert"`; из поля Enter повторяет вход (сеть, 429), а 401 правится там же |
| «Создать чат»: ошибка валидации или отказ `CheckAccount` | поле номера | так же |

- *Не `autoFocus`:* тот же эффект, но `jsx-a11y/no-autofocus` в линтере; эффект в композере явно
  привязан к «открыли чат».
- *Фокус на тексте ошибки входа отвергнут:* нужен `tabIndex={-1}`, двойное чтение вместе с `alert`,
  а исправлять всё равно в полях.
- *Клавиатурная навигация по списку:* Tab только переводит фокус, чат открывается по Enter/клику —
  фокус уходит в поле лишь по явному действию.
- *Край:* «Перейти в чат» на **уже открытый** чат — перемонтажа нет, фокус остаётся в форме.
- *Телефон:* при открытии чата может выехать экранная клавиатура — проверить вживую (К14).
- *Доступ к полям без правки кита `Input`* (`ref`/`ComponentProps` — WM-08): `name` у полей и `ref`
  на `<form>` → `form.elements.namedItem(name)` с сужением `instanceof HTMLInputElement`.

### Грабли реализации

- Первый вариант давал `key={chatId}` отдельно `MessageList` и `MessageComposer` — два соседа в одном
  фрагменте с одинаковым ключом: React путал их, и после смены чата в DOM оставались две ленты (поймал
  тест К3). Ключ — на общем `<Fragment key={chatId}>`, он пересоздаёт обоих.
- Среда: при нехватке памяти `tsgolint` (правила по типам в `npm run lint`) падает с
  `fatal error: out of memory` или `spawnSync … UNKNOWN` — это не находки линтера; освободить память
  и повторить.

## Сценарии использования

1. Пользователь проходит интерфейс Tab → кольцо фокуса тёмно-синее и видно везде: на белом, на
   активном чате, вокруг поля ввода на градиенте.
2. Собеседник отвечает при включённом скринридере → объявлено «Собеседник: <текст> <время>»; при
   открытии чата история не зачитывается.
3. Узкий экран: открыть чат → фокус в поле «Сообщение»; «Назад» → фокус на этом чате в списке.
4. Пустая форма входа → фокус в idInstance с текстом ошибки; неверный токен → фокус в idInstance.
5. Номер без MAX → фокус в поле номера; нажатие «Отправить» → фокус остаётся в поле «Сообщение».
